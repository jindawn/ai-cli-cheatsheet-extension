# Provider Adapter Catalog

Native protocol v4/v5 returns the Provider Registry from `handshake`; the browser extension does not keep a Provider allowlist. Registry entries come from:

1. `shared/provider-adapters.json` contains only the four v4-safe built-ins: Claude, Codex, Gemini and OpenCode.
2. `shared/provider-adapters-v5.json` is an optional v5-only overlay for Qwen and later v5 capabilities. If it is missing or invalid, the bridge keeps the four base environments available and reports only the v5 capability as unavailable.
3. The last valid Ed25519-signed catalog in the bridge state directory.
4. Compatible API profiles created with `aicli-cheatsheet-bridge --configure-api`.

This split deliberately keeps source-installed v3/v4 bridges working when `AICLI_PROJECT_DIR` points to a newer checkout. Those older bridges read the base file directly and must never encounter a new built-in driver they do not understand.

Signed catalog envelopes contain `payload`, its canonical `sha256`, and an Ed25519 `signature`. `catalogVersion` must increase whenever catalog content changes. The bridge rejects rollback, same-version content replacement, duplicate IDs, unsupported drivers and invalid signatures before replacing the active catalog.

The extension asks for a catalog refresh only after a user clicks **检测** or starts a
maintenance action. The bridge then refreshes only when no valid catalog exists or
the last successful check is at least seven days old. A failed refresh keeps the
last verified catalog and waits one hour before retrying; normal startup never
contacts the bridge or the network.

Catalog Provider IDs use `catalog:<slug>`. A CLI adapter declares only executable basenames, a fixed argument array, an optional non-generating login probe and one supported output driver:

- `stdin-json`: prompt on stdin, JSON on stdout.
- `jsonl-events`: prompt on stdin or as one final argument, JSONL text events on stdout.
- `output-file-json`: prompt on stdin or as one final argument, JSON in `{outputFile}`.

Allowed path placeholders are `{schemaFile}`, `{outputFile}` and `{workDir}`. They are generated by the bridge. Shell strings, pipes, redirection, command substitution, arbitrary executable paths and model-returned code are never executed.

## 用户确认的通用调用

常见目录未提供签名适配器、或用户输入其他工具名称时，桥接先把名称规范化为 PATH 中的可执行文件名并执行受限的版本探测。找不到时，扩展才会要求补充一个实际命令名。找到后必须经过一次明确风险确认，才会在桥接状态目录保存 `custom:<uuid>` Provider。

这类 Provider 的 `executionMode` 为 `generic`：启动数组固定为 `[executable]`，没有额外参数，任务提示通过标准输入传递，标准输出必须包含可解析的结构化 JSON；工作目录、15 分钟超时和取消机制仍由桥接控制。它不代表只读调用，不能宣称 CLI 不会写入、联网或请求权限；每次模型任务仍要求用户确认用量。非 JSON 输出、超时、未登录或运行失败不会写入数据，也不会改用其他 Provider。

1.7.4 及更早版本保存的自定义适配器会以 `legacy-configured` 方式继续加载，以免破坏已有用户配置。它们可以删除，但扩展不再显示旧版参数、输出驱动或登录提示编辑表单。

The release secret `PROVIDER_CATALOG_SIGNING_KEY` is the Base64 encoding of a 32-byte Ed25519 seed. Release builds derive and bundle only its public key. Use `tools/provider-catalog.py` to write the public key, sign a catalog and verify the resulting envelope.
